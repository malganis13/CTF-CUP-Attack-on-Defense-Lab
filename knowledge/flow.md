# Поток значений и ветвление: находки, которые шаблон не видит

Правила сканера смотрят на строку. Из-за этого два класса дыр проходят мимо:
значение, которое доехало до опасного вызова через присваивания, и проверка,
которая стоит не на том пути. `adkit/flow.py` закрывает оба — не доказательством,
а обоснованным подозрением.

## Что считается находкой

**`flow-taint-*`** — значение пришло из запроса и дошло до стока через одну или
несколько переменных:

```python
raw = request.args.get("name")     # источник
name = raw.strip()
target = os.path.join(base, name)
open(target)                       # сток: строкой выше нет ни request, ни кавычек
```

Находка несёт `source_line` и цепочку в объяснении. Проверять её так же, как
обычную: отправьте путь с `../` и посмотрите, что вернётся.

Поток снимают: `int()`, `parseInt`, `strconv.Atoi`, `basename`, `realpath`,
`secure_filename`, белый список, `shlex.quote`, регулярка на весь ввод.
Параметризованный запрос (`execute("... %s", (x,))`) дырой не считается.

**`flow-guard-bypass`** — в функции есть проверка подписи, но одна ветка
выходит раньше неё:

```python
if limit is not None and limit <= 3:
    return json.loads(base64.urlsafe_b64decode(token.split(".")[0]))
...
if not hmac.compare_digest(sign(payload), sig):
    raise ValueError("bad signature")
```

Подпись проверяется — но не на этом пути. Так устроен обход в starpost:
`limit=3` включает разбор курсора без HMAC.

**`flow-auth-by-value`** — авторизация сравнением структуры, которую можно
собрать из открытых данных (`cube.multiply(...) != stored`). Это cubic (2020) и
родственные протоколы. Находка самая слабая: дыра только если структура
допускает сборку без секрета.

## Почему фиолетовая плашка «проверить»

Уровень «уверен» у потока не выдаётся никогда: вывод опирается на присваивания
и порядок веток, а не на один вызов. Поэтому такие находки помечены отдельно —
`проверить`, фиолетовым, и это не важность, а метод получения. В списке
находок есть фильтр «проверить: N», в детали — блок с объяснением, почему это
не шаблон; плашка видна и в карте, и на стенде.

Порядок разбора: сначала шаблонные `уверен`, потом `проверить`. Смысл простой:
шаблонную дыру сосед закроет скриптом в первом раунде, а потоковую — только вы,
если успеете прочитать ветку.

## Что поток не умеет

- Межфайловый анализ: связь между модулями не прослеживается.
- Вызов по функции с возвратом значения (`x = build(uid); execute(x)`) — один
  уровень, не больше.
- Динамические языки со `getattr`/`eval` в середине цепочки.
- Гонки, second-order и бизнес-логику — это следующий слой, не этот.
- Математику протокола: cubic ловится по форме сравнения, а не по тому, что
  группа кубика Рубика допускает сборку.

## Проверка

`tools/test_flow.py` — 20 проверок: синтетика на поток, `int()`,
параметризованный запрос, ветка до проверки, безопасный порядок, авторизация
структурой, плюс реальные starpost и cubic. Если корпусов нет на машине,
корпусные проверки пропускаются.

Регрессия по годам (`tools/test_cup_years.py`) теперь тоже считает поток: на
GoCTF-2026 находок стало 34 вместо 31, на 2020 — 5 вместо 4, на 2024 — 8 вместо
7. Ровно те три случая, которые раньше были ручными.
