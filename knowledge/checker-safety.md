# Чекер: что считается безопасным

Приложение построено так, чтобы любой исходящий запрос проходил один фильтр —
и этот файл описывает фильтр словами, чтобы его можно было проверить глазами.

## Разрешено

| Операция | Почему |
|---|---|
| `GET` на ручку сервиса | не меняет состояние |
| `HEAD` | не меняет состояние |
| Чтение файла через SFTP | только чтение |
| `ss`, `ps`, `find`, `sed -n`, `ls`, `cat` через SSH | только чтение |
| `docker ps`, `kubectl get`, `systemctl list-units` | только чтение |

## Запрещено

| Операция | Почему |
|---|---|
| Любой запрос к `/_checker/*` | это не ваш сервис |
| `POST` / `PUT` / `PATCH` / `DELETE` в сгенерированной пробе | меняет состояние |
| `subprocess`, `os.system`, `eval`, `exec` в пробе | выходит за рамки запроса |
| `open(..., "w"/"a")` в пробе | пишет файл |
| `systemctl restart`, `docker restart`, `rm -rf` | ломает SLA |
| Обход в ширину по id (1..10000) | объёмный трафик |

## Как это проверяется

1. **AST-линтер** (`adkit/lint.py`) парсит сгенерированный код и отклоняет
   запрещённые вызовы, строки и режимы открытия файла. Результат виден в
   панели Generator.
2. **Шаблоны** (`adkit/generate.py`) физически не содержат `POST`: обычный
   шаблон — только `urllib.request` с GET. Всё, что требует изменения
   состояния, уходит в инертный шаблон с пометкой `MANUAL REVIEW`.
3. **Аудит** (`adkit/audit.py`) исполняет фиксированный скрипт. Список команд
   виден в разделе Connect и в панели Rules.

## Почему это не флуд

Числа, а не обещания. Всё ниже проверяется тестом `tools/test_probe.py`.

| Свойство | Значение | Почему это важно |
|---|---|---|
| запросов на одну пробу | ≤ 14 (+1 базовый) | это единицы запросов, а не тысячи |
| пауза между запросами | 0.15 с, минимум 0.10 с | нет залпов, нет параллельных соединений |
| запросов на процесс | 30 за 60 с | 0.5 запроса в секунду на всё приложение |
| параллельность | нет | один поток, последовательные запросы |
| метод | только GET | нет записи, нет изменения состояния |
| тело запроса | нет | GET без `data=` |
| перебор id | нет | IDOR проверяет ±1 и +2, не 1..10000 |
| повторы | нет | один проход по списку, без ретраев |
| редиректы | не переходятся | редирект — улика, а не приглашение |
| ответ | читается ≤ 64 КБ | не тянем гигабайты |
| чекер | заблокирован до отправки | путь с `/_checker` не уходит в сеть |

Токен-бакет (`adkit/ratelimit.py`) списывает бюджет **до** первого запроса.
Если бюджета нет — проба не начинается вовсе, API отвечает `429` и называет
срок повтора. Двадцать нажатий «Запустить пробу» подряд не дадут двадцать
прогонов: после 30 запросов кнопка упрётся в бюджет на минуту.

Чего здесь нет и не будет: UDP, сырых сокетов, спуфинга источника,
амплификации, параллельных воркеров, «прогрева» соединений. Инструмент не
умеет генерировать нагрузку — у него нет для этого ни кода, ни параметров.

Аудит по SSH тоже не создаёт трафика в сторону сервисов: это один SSH-сеанс,
фиксированный набор команд (`ss`, `ps`, `find` с `head`, `sed -n`), чтение
файлов через SFTP с потолком 256 КБ на файл.

## Остаточный риск

Линтер — фильтр, а не доказательство. Проба, прошедшая линтер, всё равно
запускается руками и всё равно смотрится глазами. Первый запуск — на своей
копии сервиса. Бюджет ограничивает приложение, но не отменяет правила турнира:
если регламент запрещает какой-то вид запросов, его не делает и проба.
