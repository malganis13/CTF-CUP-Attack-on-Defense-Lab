# Чекер: что считается безопасным

Приложение построено так, чтобы любой исходящий запрос проходил один фильтр —
и этот файл описывает фильтр словами, чтобы его можно было проверить глазами.

## Разрешено

| Операция | Почему |
|---|---|
| `GET` на ручку сервиса | не меняет состояние |
| `HEAD` | не меняет состояние |
| Чтение файла через SFTP | только чтение |
| `ss`, `ps`, `find`, `sed -n`, `ls`, `cat` через SSH | только чтение |
| `docker ps`, `kubectl get`, `systemctl list-units` | только чтение |

## Запрещено

| Операция | Почему |
|---|---|
| Любой запрос к `/_checker/*` | это не ваш сервис |
| `POST` / `PUT` / `PATCH` / `DELETE` в сгенерированной пробе | меняет состояние |
| `subprocess`, `os.system`, `eval`, `exec` в пробе | выходит за рамки запроса |
| `open(..., "w"/"a")` в пробе | пишет файл |
| `systemctl restart`, `docker restart`, `rm -rf` | ломает SLA |
| Обход в ширину по id (1..10000) | объёмный трафик |

## Как это проверяется

1. **AST-линтер** (`adkit/lint.py`) парсит сгенерированный код и отклоняет
   запрещённые вызовы, строки и режимы открытия файла. Результат виден в
   панели Generator.
2. **Шаблоны** (`adkit/generate.py`) физически не содержат `POST`: обычный
   шаблон — только `urllib.request` с GET. Всё, что требует изменения
   состояния, уходит в инертный шаблон с пометкой `MANUAL REVIEW`.
3. **Аудит** (`adkit/audit.py`) исполняет фиксированный скрипт. Список команд
   виден в разделе Connect и в панели Rules.

## Остаточный риск

Линтер — фильтр, а не доказательство. Проба, прошедшая линтер, всё равно
запускается руками и всё равно смотрится глазами. Первый запуск — на своей
копии сервиса.
