# Ручной аудит с нуля

Практика для первого раза: что делать по шагам, когда команда не знает ничего,
а раунд уже идёт. Инструмент ускоряет этот текст, но не заменяет его.

Главное правило: **на A/D ты не ищешь все дыры. Ты ищешь те, которые сосед
щёлкнет первым.** Это почти всегда шаблон: SQL-склейка, `../`, `;id`, IDOR по
номеру, открытый служебный файл. Сложные дыры — после.

---

## 0. Что вокруг происходит

- **Чекер** раз в раунд кладёт в сервис флаг и проверяет, что сервис его
  отдаёт. Пока чекер зелёный — очки капают. Сломал сервис — теряешь больше,
  чем принесла бы любая атака.
- **Соседи** автоматизированы. Их скрипт перебирает известные шаблоны по всем
  сервисам. Твоя задача — чтобы в первые 10 минут после выкатки их скрипт
  ничего не нашёл.
- **Флаг** — строка вида `CTF{...}`. Она лежит в базе или в файле сервиса.
  Никогда не трогай `/_checker/*`: это дисквалификация, а не хитрость.

---

## 1. Первые 30 минут (до первого раунда)

1. **Проверь, что сервис живой.** Открой его как пользователь: главная, вход,
   список объектов. Если не открывается — это задача №1, а не аудит.
2. **Сними карту.** На vulnbox:

   ```bash
   ss -lntp                 # кто слушает и на каком порту
   ps aux | grep -v grep    # чем запущено
   ls -l /proc/<pid>/cwd     # откуда запущено — это корень сервиса
   ```

3. **Забери код к себе.** Один раз, до начала раунда:

   ```bash
   ssh root@vulnbox 'tar czf - /srv/app' | tar xzf - -C ./services/
   ```

   Дальше работаешь с локальной копией: читать и искать быстрее, чем по SSH.
4. **Запусти аудит** (SSH или архив — без разницы) и **прочитай отчёт
   целиком**, сверху вниз. Список уже отсортирован: шаблонные и дешёвые
   находки идут первыми.
5. **Создай двух пользователей** в каждом сервисе. Два своих аккаунта — это
   половина всех проверок авторизации. Сохрани их куки в браузере.

Тридцать минут — и у тебя есть: карта, код, отчёт и два аккаунта.

## 2. Круг разбора одной находки — 10 минут

Находка — это кандидат. Дальше три вопроса, всегда в этом порядке.

**Вопрос 1. Откуда приходит значение?**
Открой файл на указанной строке. Проверь, что параметр действительно из
запроса, а не из конфига. Если из конфига — закрывай находку и иди дальше.

**Вопрос 2. Долетит ли оно до опасного вызова без проверки?**
Ищи между входом и вызовом: `int()`, приведение типа, белый список,
регулярка, `os.path.basename`, `shlex.quote`. Есть проверка — вопрос 3.

**Вопрос 3. Можно ли проверку обойти?**
Проверки ломаются одинаково во всех языках:

| проверка | чем ломается |
|---|---|
| `int(x)` / `Integer.parseInt` | ничем, это хорошая проверка |
| `x.replace("../", "")` | `....//` — после замены снова `../` |
| `endswith(".html")` | `file.txt?a=.html` — строка запроса не входит в путь |
| `if role == "user"` | `role=admin` в теле, если поле приходит от клиента |
| `in` по чёрному списку | регистр, юникод, двойное кодирование |
| `startsWith("/srv")` | `/srv/../../etc/passwd` |

Если ответ «проверки нет» или «обходится» — это дыра. Проверяй запросом.

**Правило таймбокса:** 15 минут на находку. Не понял — записал в список
«позже» и перешёл к следующей. На A/D порядок важнее глубины.

## 3. Порядок, в котором закрывать

1. **Служебные файлы и отладка.** `.git`, `backup.zip`, `users.txt`, `debug`,
   `/metrics`, `.env`, база в `wwwroot`. Закрывается за минуту, а отдаёт всё.
2. **SQL-склейка.** Одна строка правки, сосед найдёт её сразу.
3. **Обход пути и командная инъекция.** Тоже минуты.
4. **Авторизация.** Здесь нужен второй аккаунт: проверить, что чужой объект
   не отдаётся по номеру.
5. **Mass assignment и логика.** Поля `role`, `isAdmin`, `userId` из тела.
6. **Десериализация, SSRF, загрузка.** Структурно, но всё ещё шаблонно.
7. **Память в C/C++ и слабая крипта.** Долго, идёт последним.

## 4. Ручные проверки: команды

Ниже — минимальный набор. Подставь свой хост, порт и куку.

### SQL-инъекция

```bash
curl -s 'http://h:8080/notes?id=1%27' | head -30            # ошибка?
curl -s 'http://h:8080/notes?id=1%20AND%201=1' | wc -c      # размер
curl -s 'http://h:8080/notes?id=1%20AND%201=2' | wc -c      # должен отличаться
```

Разный размер при `1=1` и `1=2` — инъекция есть, даже если ошибки не видно.

### Обход пути

```bash
curl -s 'http://h:8080/file?name=../../../../etc/passwd' | head -3
curl -s 'http://h:8080/file?name=....//....//etc/passwd' | head -3
```

Ищи `root:x:0:0:`. Если отдаёт — читай конфиг сервиса, там строка подключения
и пароль чекера.

### Командная инъекция

```bash
curl -s 'http://h:8080/ping?host=127.0.0.1;id'
curl -s 'http://h:8080/ping?host=$(id)'
```

Ищи `uid=`. Если фильтр режет `;` — пробуй `%0aid`, `|id`, `&&id`, `` `id` ``.

### SSTI

```bash
curl -s 'http://h:8080/render?name={{7*7}}'
```

Ответ содержит `49` — шаблон исполняется. Дальше `{{config}}` или
`{{''.__class__.__mro__}}` для Python.

### IDOR — самая частая дыра на A/D

Нужны два аккаунта: A и B. Создай объект под A, запомни его номер, попроси
его под B:

```bash
curl -s -H 'Cookie: session=A' http://h:8080/notes/41
curl -s -H 'Cookie: session=B' http://h:8080/notes/41
```

Оба `200` и одинаковое тело — объект не привязан к владельцу. Это уже чужие
данные, и именно так забирают флаги соседей.

Ещё быстрее — без куки:

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://h:8080/notes/41
```

`200` без сессии — маршрут не закрыт вообще.

### Массовое присваивание (mass assignment)

```bash
curl -s -X POST http://h:8080/profile -H 'Cookie: session=A' \
     -H 'Content-Type: application/json' -d '{"displayName":"x","role":"admin"}'
curl -s -H 'Cookie: session=A' http://h:8080/me
```

Если в `/me` появилось `role: admin` — поле приняли из тела. Так же проверяются
`isAdmin`, `balance`, `userId`, `ownerId`, `verified`.

### JWT

```bash
# alg:none
printf '%s' '{"alg":"none","typ":"JWT"}' | base64 -w0
```

Собери токен `header.payload.` (подпись пустая) и подставь в `Authorization`.
Если сервис принял — проверки подписи нет.

### Загрузка файла

Загрузи `test.php` с содержимым `<?php echo 1; ?>` и открой по прямому пути.
Работает — это исполнение кода. Не работает — попробуй `test.pHp`, `test.php.jpg`,
`test.php%00.jpg`.

### SSRF

```bash
curl -s 'http://h:8080/fetch?url=http://127.0.0.1:80/'
curl -s 'http://h:8080/fetch?url=http://169.254.169.254/latest/meta-data/'
```

Отвечает своим же телом или метаданными — сервер ходит куда сказали.

## 5. Где смотреть в коде, по стеку

**Python / Flask / FastAPI.** `request.args`, `request.form`, `request.json` —
это вход. `execute`, `open`, `subprocess`, `render_template_string`, `eval` —
это выход. Ищи, соединяется ли одно с другим.

**Node / Express.** `req.query`, `req.body`, `req.params` → `query`, `exec`,
`readFile`, `res.render`. Отдельно: `jwt.decode` (без `verify`) — это не проверка.

**PHP.** `$_GET`, `$_POST`, `$_REQUEST` → `query`, `include`, `system`, `eval`,
`unserialize`, `move_uploaded_file`. PHP 8 меньше страдает от типов, но
`==` вместо `===` всё ещё ломается.

**Go.** `r.URL.Query().Get`, `c.Param` → `db.Query` со `Sprintf`, `exec.Command`,
`os.ReadFile`. Go безопасен по умолчанию: любая склейка строки в SQL —
осознанная ошибка автора сервиса.

**C# / ASP.NET.** `[HttpPost]` + параметр-сущность (`CreatePost(Wrapper w)`) —
модель-биндер заполнит все поля, включая `UserId`. `Request.Form[...]` —
вход. `Password = ...` без хеша — пароли открытым текстом.

**C / C++.** `strcpy`, `sprintf`, `memcpy` с длиной из ввода — переполнение.
`system`, `popen` — команда. В бинарнике это видно по импортам, даже без
исходников.

## 6. Что делать после правки

Порядок неизменный:

1. **Бэкап файла:** `cp app.py app.py.bak-$(date +%H%M)`.
2. **Правка.** Минимальная. Одна дыра — одна правка.
3. **Перезапуск:** `systemctl restart app` и сразу `systemctl is-active app`.
4. **Своя проверка:** тот же запрос, что давал дыру, должен перестать работать.
5. **Чекер:** дождись раунда. Если чекер красный — откат из бэкапа первым делом,
   разбор потом. Очки за сломанный сервис теряются быстрее, чем приходят.
6. **Повторный аудит:** находка должна исчезнуть, а новых появиться не должно.

Правка, после которой чекер красный, — не «почти получилось», а откат.

---

## 7. Три правила новичка

1. **Не трогай чужое.** Только свой vulnbox. `/_checker/*` — не читать, не
   писать, не проверять.
2. **Не ломай то, что работает.** Любая правка — с бэкапом и с проверкой
   чекером. Сервис, который отдаёт флаг, приносит больше очков, чем любая атака.
3. **Пиши, что сделал.** Одна строка на действие: время, файл, что поменял,
   что проверил. Через час ты не вспомнишь, а команда спросит.

---

## 8. Когда звать на помощь и что говорить

Если через 15 минут не понял находку — не сиди в ней. Скажи команде так:

> «`/srv/app/handlers/auth.go:104` — `WHERE id = $1` без владельца, вход
> `GET /balance?id=`. Кука B получает тот же ответ. Нужно решение: закрывать
> через `AND owner_id = $2` или проверять в хендлере?»

Это три факта: где, почему опасно, что уже проверено. С таким сообщением
помощь приходит за минуту.
