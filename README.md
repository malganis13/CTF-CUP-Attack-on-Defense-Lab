# AD Audit

Локальный read-only аудитор сервисов для Attack–Defense. Читает исходники —
по SSH с vulnbox или прямо из архива сервиса, без SSH вообще, — собирает карту
сервисов, находит опасные места и показывает их с файлом и строкой. Генерирует
безопасные GET-пробы, проверяет, закрыт ли маршрут авторизацией, собирает
markdown-отчёт и unified diff для правки.

Веб-интерфейс, один код на Arch Linux и Windows 11, без внешних зависимостей
кроме опционального `paramiko`.

## Что это

- Инструмент **триажа**: где в коде вход из запроса встречается с опасным
  вызовом.
- Инструмент **карты**: какие порты слушают, какой процесс, из какого каталога.
- Инструмент **отчёта**: markdown, который можно показать команде.

## Чего это не делает

- **Не гарантирует флаг.** Находка — кандидат; доказательством её делает проба
  с маркером. Проба проверяет только GET-классы.
- **Не генерирует POST-эксплойты.** Всё, что меняет состояние, выходит
  инертным шаблоном с пометкой `MANUAL REVIEW`.
- **Не применяет патчи.** Лечение — код до/после, шаги и готовый `.patch`;
  накладывает человек.
- **Не заменяет чтение кода.** Сканер видит строку, не поток данных.

## Платформы

Один код, два лаунчера. Различия сведены к трём строкам.

| | Windows 11 | Arch Linux |
|---|---|---|
| лаунчер | `run.ps1` | `run.sh` (нужен `chmod +x`) |
| python | 3.10+ | 3.10+ |
| ssh-клиент | встроенный OpenSSH (проверено на 9.5p2) | `openssh` |
| вход по паролю | `paramiko` | `paramiko` |
| вход по ключу | системный `ssh` или агент | системный `ssh` или агент |
| кириллица в консоли | UTF-8 в `run.ps1` + BOM в файле | `PYTHONIOENCODING=utf-8` в `run.sh` |
| переводы строк | `.gitattributes`: `run.sh` — LF, `*.ps1` — CRLF | то же |

Проверка окружения на любой машине:

```bash
python tools/check_platform.py
```

Скрипт смотрит версию Python, наличие `ssh`, `paramiko`, право запуска
`run.sh` в git, BOM у `run.ps1`, переводы строк, демо-данные. Выходит с кодом 1,
если что-то сломается при переносе.

### Что уже поймано при переносе

- `run.sh` лежал в git с правами `100644` — после клона на Arch не запускался.
  Исправлено: `git update-index --chmod=+x`, теперь `100755`.
- `[[ … ]] && echo` под `set -e` ронял `run.sh` без флага `--demo`.
  Исправлено на `if … then … fi`.
- PowerShell 5.1 читает `.ps1` без BOM как ANSI: кириллица в строках ломала
  парсер (`TerminatorExpectedAtEndOfString`). Исправлено: UTF-8 с BOM.
- Кириллица в консоли Windows выводилась мусором. Исправлено:
  `[Console]::OutputEncoding = UTF8` в лаунчере и `reconfigure(encoding="utf-8")`
  в инструментах.

## Установка

Нужен Python 3.10+.

**Arch Linux**

```bash
sudo pacman -S python python-pip
cd ad-audit
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt      # опционально: только для пароля
chmod +x run.sh
```

**Windows 11**

```powershell
winget install Python.Python.3.12     # если ещё нет
cd ad-audit
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

`paramiko` нужен только для входа по паролю. Без него используется системный
`ssh` — ключ или агент.

Браузер: Chrome, Edge (Chromium) или Firefox. Старый Edge (EdgeHTML) и режим IE
не выполняют скрипт интерфейса — приложение покажет сверху баннер с причиной.
Если в учебном классе открывается старый Edge, скопируйте адрес
`http://127.0.0.1:8765` в Chrome: сервер уже запущен, менять ничего не нужно.

## Пароли и службы на цели

Данные доступа живут в памяти процесса: `config.json` хранит хост, порт,
пользователя, способ входа и путь к ключу — пароль туда не попадает.

- Поле **пароль** видно всегда; оно нужно, когда вход по паролю. В собранном
  exe paramiko уже внутри, отдельная установка не требуется.
- **Проверить связь** печатает точный адрес, к которому подключился:
  `root@127.0.0.1:2222 (paramiko)`. Если это не та машина — ошибка в порту
  или адресе, а не «связь есть» без объяснений.
- **Смена пароля на цели** вызывает `chpasswd` и передаёт пароль через stdin:
  он не виден в `ps` на цели, не пишется в `config.json` и в журнал. После
  смены инструмент проверяет вход новым паролем отдельным соединением и
  показывает результат.
- **Сервисы на цели** (вкладка «Стенд») читает `ss -lntp`, запущенные юниты
  systemd, каталоги `/srv`, `/opt`, `/home` и `docker ps` — один SSH-заход,
  без сканирования снаружи. Кнопка «в стенд» переносит найденные порты в
  модель стенда.

Политику `PermitRootLogin` инструмент показывает рядом с результатом: если
sshd запрещает root по паролю, пароль сменится, но вход по нему не откроется,
пока не поправить `/etc/ssh/sshd_config.d/*.conf`. Подробный порядок, смена
пароля БД и проверка чекера — `knowledge/vuln.md`.

## Без SSH

Второй вход в тот же движок: поле «без SSH: каталог или архив сервиса» на
вкладке **Аудит**. Указывается каталог с исходниками или архив — `.zip`,
`.tar.gz`, `.tgz`, `.tar.bz2`, `.tar.xz`. Архив распаковывается во временный
каталог, элементы с `..` и абсолютными путями отклоняются до записи, после
скана временный каталог удаляется.

Когда это нужно:

- сервис пришёл архивом с площадки, а не машиной с SSH;
- чужой ноутбук без доступа к vulnbox;
- разбор чужого райтапа или корпуса прошлого Кубка: `veladora.zip` → 33 находки
  за прогон, без единого пакета наружу;
- проверка собственной правки до выкатки.

Отличия от SSH-прогона ровно два: нет карты портов и процессов (её не из чего
собрать) и пути в отчёте — относительные, от корня архива. Правила, приоритеты,
лечение и патчи работают те же.

## Пробы и заготовки

**Проба** — не «дёрнуть страницу», а настоящая проверка. Для класса находки
берётся фиксированный набор полезных нагрузок, каждая уходит GET-запросом, и в
ответе ищется маркер:

| класс | нагрузки | маркер |
|---|---|---|
| SQL injection | `'`, `"`, `\`, `1' OR '1'='1` | текст ошибки SQL |
| Path traversal | `../../etc/passwd`, `....//`, `%2e%2e%2f`, `/etc/passwd` | `root:x:0:0:` |
| Command injection | `;id`, `\|id`, `$(id)`, `` `id` `` | `uid=…(…)` |
| SSTI | `{{7*7}}`, `${7*7}`, `<%= 7*7 %>`, `#{7*7}` | `49` |
| Open redirect | `//example.org`, `https://example.org/` | `Location:` в заголовках |
| SSRF | `http://127.0.0.1:{port}/`, metadata | тело/статус отличаются от базового |
| IDOR | id ±1, +2 | 200 и другое тело |

Результат — таблица: метка, статус, байты, миллисекунды, вердикт
(`сигнал` / `отличие` / `чисто` / `ошибка` / `заблокировано`), улика.

**Пара авторизации.** Перед полезными нагрузками тот же путь запрашивается
дважды: без сессии и с кукой из поля «кука сессии» (хранится только в памяти).
Вердикт:

| вердикт | что значит |
|---|---|
| `маршрут не закрыт` | без сессии 200, страницы входа нет — или ответ дословно тот же, что с сессией |
| `маршрут закрыт` | 401/403, редирект на вход, либо страница входа с кодом 200 |
| `не определить` | сервер ответил, но отличить вход от заглушки нельзя |

Это единственная проверка авторизации, которой не нужен второй аккаунт и не
нужна запись: она сравнивает два чтения одного и того же. Без куки она
отвечает на вопрос «пускает ли анонима», с кукой — «и отдаёт ли ему то же,
что вошедшему».

**Два аккаунта (BOLA).** Если заполнена вторая кука, вместо пары считается
три чтения: аноним, аккаунт A, аккаунт B — один и тот же путь.

| вердикт | что значит |
|---|---|
| `объект виден обоим` | A и B получили 200 и одинаковое тело — объект не привязан к владельцу |
| `объект закрыт владельцем` | B получил 401/403/404 |
| `ответил обоим, объекты разные` | 200 обоим, тела разные — маршрут пускает, но отдаёт разное |
| `у A нет доступа` | сначала надо получить объект под A |

Это и есть доказательство «A видит объект B», а не догадка: два своих
аккаунта, три запроса, ноль записи.

**POST — за флагом.** По умолчанию инструмент отправляет только GET. Галочка
«разрешить POST» рядом с кнопкой запуска добавляет один запрос на класс:
mass assignment (`{"role":"admin"}`), отрицательная сумма, владелец из тела.
Запись меняет состояние, поэтому флаг снят по умолчанию и включается на своей
копии сервиса, а не на чужой.

**Заготовка** — для того, что нельзя проверить одним GET (mass assignment,
upload, JWT, десериализация). Это полный конструктор запроса: multipart,
JSON, form, подделка `alg:none` JWT — всё в коде. По умолчанию печатает
запрос, отправляет с `--send`.

Обе вещи проверяет AST-линтер в двух режимах: `probe` (строгий) и `scaffold`
(разрешает изменение состояния, но перечисляет его предупреждениями).


## Контракт «только чтение»

SSH-скрипт аудита исполняет фиксированный набор команд:

```
id, uname, cat /etc/os-release, hostname, ss -lntup, ps auxww,
systemctl list-units --type=service, docker ps/images, kubectl get,
crontab -l, env, ls, find, sed -n '1,200p'
```

Ни записи, ни рестартов, ни `systemctl start/stop`, ни изменений в файлах.
Чтение исходников — через SFTP (`paramiko`) или `head -c` (системный `ssh`).

Сгенерированная проба проходит через AST-линтер и отклоняется, если содержит
`POST/PUT/DELETE`, `/_checker`, `putflag`/`getflag`, `subprocess`, `os.system`,
`eval`, `exec`, запись файла или изменение состояния. Подробности —
`knowledge/checker-safety.md`.

## Демо

```bash
python tools/build_demo.py     # пересобрать demo/audit.json из demo/src
./run.sh --demo
```

`demo/src/` — двенадцать сервисов на десяти языках: Python (`notes`, `files`,
`profile`), Go (`gateway`), Rust (`rustapp`), JavaScript (`api`), PHP (`portal`),
Java (`billing`), C# (`support`), C (`legacy`), Ruby (`lookup`), Lua (`luaapp`).
Каждый — намеренно уязвимый исходник плюс манифест (`go.mod`, `Cargo.toml`,
`package.json`, `composer.json`, `pom.xml`, `*.csproj`, `Gemfile`), чтобы демо
показывало и находки, и определение стека.

Они никогда не импортируются и не запускаются: сканер читает их как текст.
Пересборка демо идёт через тот же движок, что и живой аудит, поэтому демо
показывает ровно те правила, которые поставляются.

## Нагрузка и бюджет

Инструмент спроектирован так, чтобы его нельзя было принять за генератор
нагрузки. Числа проверяются тестом `tools/test_probe.py`:

| свойство | значение |
|---|---|
| запросов на пробу | ≤ 14 полезных + 1 базовый + 2 пара авторизации (3 с двумя куками) |
| пауза между запросами | 0.15 с, минимум 0.10 с |
| запросов на процесс | 30 за 60 с (токен-бакет) |
| параллельность | нет, последовательно |
| метод | GET; POST только с явной галочкой, один на класс |
| перебор id | нет |
| редиректы | не переходятся |
| ответ | ≤ 64 КБ |

Бюджет списывается **до** первого запроса: без бюджета проба не начинается,
API отвечает `429` со сроком повтора. Ни UDP, ни сырых сокетов, ни
параллельных воркеров в коде нет.

## Проверка

```bash
python tools/test_probe.py       # 42 проверки: детект на живом HTTP, ложные
                                 # срабатывания, чекер, пауза, бюджет, линтер
python tools/test_authdiff.py    # 18: пара «без сессии / с сессией», два
                                 # аккаунта (BOLA), POST за флагом
python tools/test_deps_cve.py    # 21: манифесты -> версии, встроенные CVE,
                                 # разбор настоящего ELF и его защит
python tools/test_offline_patch.py  # 12: zip без SSH, защита от выхода за
                                 # каталог, git apply --check на реальном файле
python tools/smoke.py            # 131 проверка: все ручки API и панели
python tools/test_cup_years.py   # 11 корпусов: заложенное найдено, no regress
python tools/test_confidence.py  # уверенность: уровни, план, детерминизм
python tools/test_journal.py     # журнал: закрытие, возврат, разница прогонов
python tools/test_topology.py    # стенд: модель, импорт, привязка находок
python tools/test_flow.py        # поток значений и ветки: находки без шума
python tools/test_remote.py      # службы на цели и смена пароля без утечки
python tools/test_ui_wiring.py   # id из JS есть в HTML, вкладки не мёртвые
```

`test_probe.py` поднимает `tools/lab_server.py` — намеренно уязвимый сервер на
stdlib с пятью дырами и одной чистой ручкой. Проба должна найти пять сигналов,
не найти ни одного на чистой ручке, ни разу не обратиться к `/_checker/*` и
уложиться в бюджет. Экспортированный скрипт запускается отдельным процессом и
проверяется так же.

Конфиг после прогонов возвращается в исходное состояние.

## Языки

Сканер не предполагает Python. Правила разложены по языкам через
`Rule(languages=(...))`, файл без расширения определяется по shebang.

| Язык | Что ищется |
|---|---|
| Python | SQL, IDOR, traversal, `shell=True`, pickle, SSTI, JWT, upload |
| Go | SQL через `fmt.Sprintf`, `exec.Command`, `os.ReadFile`, роуты gin/chi/echo |
| Rust | SQL через `format!`, `.arg(format!)`, `fs::read`, `unwrap`, axum/actix |
| JS / TS | шаблонный SQL, `eval`, `fs.readFile`, `exec`, `innerHTML`, `jwt.decode` |
| PHP | `$_GET` в запрос, `system`, `eval`, `include`, `unserialize`, upload |
| Java / Kotlin | SQL конкатенацией, `new File(request)`, `Runtime.exec`, Spring |
| C# | `SqlCommand` конкатенацией, `Process.Start`, `[HttpGet]` |
| C / C++ | `strcpy`/`sprintf`/`gets`, `system`, `memcpy` без `sizeof` |
| Ruby | `where("… #{…}")`, `system(params)`, `eval`, `YAML.load`, Rails |
| Lua | `loadstring`, `os.execute` |

Вкладка **Rules → Coverage** показывает это с числом правил на язык. Манифесты
(`go.mod`, `Cargo.toml`, `package.json`, `composer.json`, `pom.xml`, `Gemfile`,
`requirements.txt`, `*.csproj`, `Dockerfile`) читаются отдельно, стек сервиса
виден в колонке **stack**: `go/gin`, `php/laravel`, `rust/axum`, `javascript/express`.

## Добавить правило

`adkit/patterns.py`, кортеж `RULES`:

```python
Rule(
    id="my-rule",
    kind="My bug class",
    severity="high",                      # high | medium | low | info
    why="Что именно встретилось и почему это опасно.",
    patch="Как чинить, одной фразой.",
    pattern=re.compile(r"""..."""),
    checker_risk="low",                   # low | medium | high
    absent=("owner",),                    # слова, при которых правило молчит
),
```

Проверка:

```bash
python tools/build_demo.py
```

Если правило ловит фикстуру — оно появится в демо. Если нет — фикстура или
регулярка не те.

## Живость сервисов

Вкладка «Сервисы» отвечает на первый вопрос раунда: сервис лежит или нет.

Кнопка «Проверить живость» делает по одному `GET` на сервис и показывает:

| лампа | что значит |
|---|---|
| `не лежит` | ответ `200–399` за считанные миллисекунды; рядом — время отклика |
| `открыт` | порт открыт, но говорит не по HTTP (sshd и подобное) — сервис жив |
| `ошибки` | отвечает `5xx`: процесс есть, ручка сломана |
| `лежит` | порт закрыт или соединение не установилось |
| `loopback` | слушает только `127.0.0.1` или это UDP — снаружи его нет |

Проверка идёт через тот же бюджет и тот же журнал, что и пробы: один `GET`,
повтор не чаще раза в две секунды, путь `/_checker` заблокирован. После аудита
живость проверяется автоматически. Остановка сервиса и возврат его в строй
видны сразу: `inactive` → лампа `лежит`, `active` → `не лежит` с временем.

## Зависимости и CVE

Сканер смотрит код. Отдельный проход смотрит, что код тянет.

Разбираются манифесты: `requirements*.txt`, `pyproject.toml`, `go.mod`,
`package.json`, `composer.json`, `Cargo.toml`, `pom.xml`, `Gemfile.lock`,
`CMakeLists.txt` (`find_package(Boost …)`). Из них получается список
«экосистема, имя, версия, строка».

Дальше версия сверяется с базой:

- **OSV** (`api.osv.dev`) — живой запрос на каждую пару «пакет + версия».
  Ответ кэшируется в `state/osv-cache.json`, лимит 40 пакетов и 25 секунд на
  прогон, при первой же сетевой ошибке онлайн отключается до конца аудита.
- **встроенная таблица** — семь записей, которые встречались на A/D и в
  корпусах Кубка (flask, pyyaml, requests, lodash, jsonwebtoken, log4j-core,
  boost). Работает без сети.

«boost 1.74 используется» превращается в «boost 1.74 уязвим (CVE-2023-34399),
исправлено в 1.84». Диапазон вида `>=1.2,<2` даёт нижнюю границу с пометкой
`approximate` — врать про точную версию инструмент не будет.

## Бинарники

Для ELF читается сам файл, а не только строки: заголовок, таблица сегментов,
таблица секций, `.dynsym`/`.symtab`, `.note.go.buildid`. Из этого:

- **импорты по символам** — `system`, `popen`, `execv`, `strcpy`, `sprintf`,
  `gets` видны как импорты, а не как случайная строка в `.rodata`;
- **защиты** — `elf-exec-stack` (стек с правом X), `elf-no-pie` (ET_EXEC),
  `elf-no-canary` (нет `__stack_chk_fail`), `elf-no-relro`, `elf-writable-text`
  (сегмент одновременно W и X). Для Go и Rust канарейка не считается: её там
  не бывает по устройству рантайма;
- **язык** — Go выдаёт себя заметкой `.note.go.buildid`.

В оффлайн-режиме файл читается с диска. По SSH файл забирается целиком
(base64, до 3 МБ); если забрать не вышло — остаются строки, и это видно в
отчёте: у находки стоит `binary: true`.

## Уверенность, карта, журнал

Сканер видит форму кода, а дыра — ещё и намерение. Поэтому у каждой находки
три слоя, которых не было раньше.

**Уверенность.** Уровень `уверен` / `скорее да` / `не уверен`, причина оценки и
план ручной проверки: что отправить, что увидеть, что закроет находку. Прямой
sink с видимым входом из запроса — `уверен`; эвристика про владельца объекта —
`скорее да` или `не уверен`; бинарник без исходников и манифест зависимости —
`не уверен` всегда. Оценка детерминированная, проверяется тестом.

**Карта.** Вкладка «Карта»: класс → файл → строка, цвет по важности, плашка
уверенности и статуса, фильтры «только открытые», «только уверен», поиск.
Клик по строке открывает находку с планом и правкой. Сверху — сколько открыто
и сколько закрыто по каждому классу.

**Журнал.** `state/journal.db` (SQLite). Каждый прогон кладёт снимок; находка
узнаётся по отпечатку «правило + файл + текст строки», поэтому сдвиг строк
патчем её не теряет. Статусы: `открыта`, `закрыта` (исчезла из следующего
прогона), `вернулась` (была закрыта и снова появилась), `игнор` (решение
человека). Вкладка «Журнал» показывает прогоны, разницу «было → стало» и
позволяет менять статус вручную.

**Поиск.** Поле в шапке ищет одним запросом по находкам, правилам и базе
знаний; клик открывает нужную вкладку.

**Сортировка.** Заголовки таблиц кликабельны (важность, файл, счётчики), у
находок — отдельный селект: приоритет, важность ↓/↑, уверенность, файл, строка.

## Стенд турнира

Вкладка «Стенд» — схема целиком, не список находок. В центре сервер, вокруг
карточки сервисов: порт, язык, полоса важности, лампа живости, риск 0–100
(high весит 10, medium 4, low 1). Линии от сервера к сервису окрашены по худшей
находке. Клик по карточке открывает справа находки этого сервиса — с
уверенностью и строкой; клик по находке ведёт в её разбор.

Данные вводит человек, они лежат в `state/topology.json` и переживают
перезапуск: событие, наша команда, число команд на поле, состав, длина раунда,
имя и адрес сервера, список сервисов (имя, порт, язык, каталог, заметка).

- **«Заполнить из аудита»** добавляет сервисы, которых нет в модели, и
  заполняет пустые язык/каталог/хост. Ручные поля не перезаписываются, повторный
  импорт ничего не размножает.
- **«Правка»** — форма: добавить/убрать сервис, задать состав по одному в
  строке, поменять число команд и раунд. Сохранение атомарное (временный файл →
  переименование).
- **Поле и команда** — точки команд (наша подсвечена) и чипы состава. Число
  команд ограничено 4096, состав — 64 человека, сервисов — 32: это не
  произвольный каприз, а защита от случайной вставки простыни.
- Находки привязываются к сервису по каталогу: `file` должен начинаться с
  `cwd` сервиса. Всё, что не привязалось, показывается как «вне сервисов» с
  подсказкой задать каталог.

Клавиша `S` открывает стенд, `M` — карту, `J` — журнал.

## Поток значений и ветвление

Шаблон видит строку; `adkit/flow.py` видит файл. Три детектора:

- **поток значений.** Переменная из `request.args` проходит через присваивания
  и доезжает до `open`/`execute` на другой строке. Находка `flow-taint-*`: в ней
  указана исходная строка и цепочка, а не только место вызова. `int()`,
  `basename`, `secure_filename`, белый список снимают поток; параметризованный
  запрос (`%s` с кортежем) дырой не считается.
- **порядок веток.** Функция проверяет подпись, но одна ветка возвращает
  разобранные данные раньше проверки — `flow-guard-bypass`. Именно так обходится
  HMAC в starpost: `if limit <= 3: return json.loads(...)` до `compare_digest`.
- **авторизация равенством структуры** — `flow-auth-by-value`. Сравнение
  объекта, собранного из ввода, с сохранённым значением: cubic (2020) и подобные
  протоколы. Дыра только если структуру можно собрать без секрета — поэтому
  уверенность всегда ниже.

Находки потока помечаются фиолетовой плашкой **«проверить»** и никогда не
получают уровень «уверен»: это эвристика, её подтверждает проба. Фильтр
«проверить: N» над списком находок показывает только их; в детали есть блок с
объяснением, почему это не шаблон. В карте и на стенде плашка та же.

Проверено на корпусах: starpost — обход подписи на `limit <= 3` плюс LFI через
`Path(raw)`; cubic — сравнение куба; на 2025 и leto26 поток не даёт ни одной
находки, то есть шума на нормальном коде нет.

## Лечение находок

У каждой находки две стороны: где дыра и как закрыть, не сломав сервис.

- кнопка «Как закрыть» в детали находки показывает код **до** и **после** на
  языке сервиса (Python, Node, PHP, Go, Java, C#, Ruby, Rust, C/C++);
- рядом — риск для раунда: что может отвалиться у чекера;
- **«Скачать .patch»** — unified diff с настоящими номерами строк из того чтения,
  которым нашлась находка: `git apply` / `patch -p1` принимает его как есть
  (проверяется тестом через `git apply --check` на реальном файле);
- если рецепт написан на другом языке, чем файл, патч **не собирается**:
  python в `.go`-файле — не правка, а новая поломка. Интерфейс говорит, на каком
  языке рецепт и что переносить смысл придётся руками;
- порядок: патч → рестарт юнита → проба должна замолчать → раунд чекера должен
  остаться зелёным.

Патч не применяется инструментом и не будет: аудит read-only, а решение
остаётся за тем, кто держит чекер.

Проверено на полигоне: после параметризации SQL в `notes` находка `sql-fstring`
исчезла (18 → 17), `'` в параметре даёт `200 {"count": 0}` вместо `500`,
обычный поиск работает, чекер — `notes=OK archive=OK warehouse=OK`.

Модуль правок: `adkit/fixes.py` (20 классов, 54 правила). Сборка diff:
`adkit/patch.py`.

## Полигон A/D

`sim/` — тренировочный вулнбокс: три сервиса с настоящими дырами и чекер.

| сервис | язык | порт | что намеренно сломано |
|---|---|---|---|
| notes | Python 3 stdlib | 8081 | SQLi, traversal, command injection, pickle, unsafe upload, IDOR |
| archive | Node 22 | 8082 | SQLi, traversal, command injection, JWT без проверки, SSRF, open redirect |
| warehouse | PHP 8.4 | 8083 | LFI, SQLi, command injection, eval, unserialize |

Чекер (`sim/vulnbox/checker/checker.py`) раз в 45 с кладёт по флагу в каждый
сервис и проверяет, что сервис отдаёт его через легальную ручку. Пишет
`/srv/_checker/status.json` и `scoreboard.log`.

```bash
python tools/sim_lab.py up        # развернуть в WSL (Kali), вывести адреса
python tools/sim_lab.py status    # здоровье сервисов + последний раунд
python tools/sim_lab.py down      # остановить
python sim/patch_notes_sqli.py apply     # доказательство «лечение не ломает»
python sim/patch_notes_sqli.py restore
```

Живой прогон: аудит по SSH (root@WSL:2222) → 18 находок за ~1.1 с;
шесть классов подтверждены пробами на реальных сервисах: SQLi (1 сигнал),
traversal (2), command injection (2), SQLi Node (1), command injection Node (4),
LFI PHP (1). Чекер: три сервиса зелёные.

## Трафик: почему это не флуд

Вкладка «Трафик» показывает журнал реально отправленных запросов и потолки:

| параметр | значение |
|---|---|
| запросов на пробу | ≤ 14 GET + 1 базовый |
| пауза между запросами | ≥ 0.10 с (по умолчанию 0.15) |
| бюджет процесса | 30 запросов / 60 с, списывается до отправки |
| тело запроса | нет; только GET |
| размер ответа | ≤ 64 КБ |
| редиректы | не переходятся |
| `/_checker/*` | блокируется до отправки |

Одна проба — это 4–5 запросов за ~2 с. Обычная загрузка страницы в браузере
делает больше. Журнал выгружается в CSV — можно показать организаторам.

## Проверка перед игрой

Вкладка «Подключение» → «Проверить всё». Один SSH-проход, около секунды, без записи на цель:

| проверка | что ловит |
|---|---|
| SSH и права | нет входа, не тот пользователь, не root |
| Часы бокса | расхождение с ноутбуком: патч с меткой уезжает в чужой раунд |
| Диск `/` и `/srv` | сервису некуда писать — упадёт без ошибки в логе |
| Загрузка | кто-то уже греет машину, раунды поплывут по времени |
| Упавшие юниты | красный раунд ещё до начала |
| Чекер | имя юнита: знать и не трогать |
| Стеки | python/node/php/sqlite — есть ли чем сервису работать |
| Слушающие сервисы | аудит не запускался |
| Ключ и цель | локально: файл ключа, режим, бюджет |

Вердикт — `ок`, `внимание`, `стоп`. Стоп-пункты надо закрыть до первого раунда.

## Что изменилось после патча

После второго аудита вкладка «Находки» показывает блок «С прошлого аудита»:
сколько находок закрылось, сколько появилось, что осталось. Сравнение идёт по
хэшу «файл:строка:правило», поэтому правка в одном месте не маскирует новую дыру
в другом.

## Журнал сервиса

В строке сервиса — кнопка «логи»: `journalctl -u <юнит> -n 120`. Только чтение,
имя юнита проверяется шаблоном. Это первое, что смотрят, когда раунд покраснел.

Вкладка «Генератор» → «Тренировка перед игрой»: восемь эксплойтов, которые дают
большинство флагов на A/D.

| # | класс | запрос |
|---|---|---|

## Состояние и журнал действий

Между запусками инструмент помнит две вещи — в каталоге `state/` рядом с приложением
(или в `AD_STATE_DIR`, если задан):

- `history.jsonl` — по строке на аудит: время, счётчики, id находок. Благодаря нему
  «что изменилось после патча» работает и после перезапуска.
- `ops.jsonl` — журнал действий: аудит, проба, упражнение, проверка живости и preflight
  с временем и результатом. Это ответ на вопрос «когда я это правил».

Отдаётся через `/api/ops`. Каталог в `.gitignore`: чужая история в репозиторий не едет.

## Флаг в ответе

Любой ответ пробы или упражнения проверяется на форму `prefix{...}`. Если сервис отдал
флаг на GET — это не «ещё одна улика», это уже потерянный флаг, и он показывается
отдельной зелёной строкой с кнопкой «копировать». Отправлять его всё равно руками:
инструмент не знает адреса жюри и не должен знать.

## Ограничения

- Правила — регулярки по строкам. Межфайловый поток данных не отслеживается.
- AST-разбор есть только для Python (в линтере проб), сканер кода — регулярки.
- ELF разбирается по таблицам; дизассемблера и анализа потока управления нет.
  PE и .NET-сборки не разбираются: только строки.
- Авторизация проверяется парой «без сессии / с кукой» и парой двух аккаунтов.
  Оба аккаунта свои, куки вводит оператор.
- POST отправляется только с явной галочкой, один запрос на класс.
- CVE сверяются по версии из манифеста; лок-файлы и транзитивные зависимости
  не разбираются.
- `paramiko` без pinned host key: `AutoAddPolicy`, ключ не сверяется.
- Пароль и куки живут в памяти процесса; в `config.json` не пишутся.

## Ручной аудит

Инструмент ускоряет разбор, но не заменяет его. Порядок действий для команды
без опыта — `knowledge/manual-audit.md`: первые 30 минут, круг разбора одной
находки, ручные `curl`-проверки по классам, что делать после правки и как
сформулировать вопрос команде. Открывается во вкладке «База знаний».

Правило оттуда, которое стоит помнить отдельно: после каждой правки сначала
чекер, потом повторный аудит. Правка, после которой чекер красный, — откат,
а не «почти получилось».

Что это дало по коду:

- `adkit/audit.py` — чтение файлов больше не склеивает содержимое: маркер файла
  печатается с ведущим переводом строки, а `sed -n '1,200p'` заменён на
  `head -c 262144`. До правки файл без завершающего `\n` затягивал в свой буфер
  следующий, и номера строк уезжали (в 60-строчном файле находились находки на
  124-й строке); вторая половина любого файла длиннее 200 строк не читалась.
- `find -maxdepth 8` вместо 5: самописные библиотеки вроде
  `planner/src/tmp_libs/nodeorm/lib/model.js` лежали глубже и в аудит не попадали.
- `adkit/languages.py` — `cwd == "/"` больше не даёт объединения всех стеков
  (sshd числился «javascript»).
- Новые правила: `py-key-truncation`, `py-static-iv`, `py-xor-reuse`,
  `js-weak-sanitizer`, `cs-weak-token` (контекстное), `php-laravel-idor`,
  `php-laravel-ssrf`, `crypto-custom-cipher`, `logic-balance-update`,
  `logic-missing-owner-check`.
- Правила 1.7–1.8, закрывшие 2020–2024: `cs-unsafe-deserialization`,
  `cs-debug-page`, `cs-unsafe-pointer`, `cs-dead-ttl` (TTL, который никогда не
  срабатывает), `nginx-cookie-upstream` (кука → upstream), `mongo-nosql-request`,
  `py-dynamic-dispatch` (`globals().get` из запроса), `py-eval`,
  `py-jwt-noverify`, `py-sql-concat` (многострочная склейка),
  `py-owner-from-request`, `dj-auto-approved` (дружба `default=True`),
  `c-prefix-compare`, `c-index-from-input`, `cpp-unsigned-index`,
  `rust-path-join`, `static-sensitive-file`. Всего 94 правила.
- Сборки и вендоренный код не сканируются: `*.min.js`, `chunk-*`, каталоги
  `vendor/`, `node_modules/`, заголовки длиннее 800 строк — они давали ложные
  находки в `three.core.min.js` и `crow/json.h`.
- Бинарники: ELF ищется по магии, строки читаются `strings` (или `tr`, если
  binutils нет) и проверяются на `/bin/sh`, `system`, `strcpy`, приватный ключ и
  флаг. Найденное помечается `binary: true` и строкой 0.
- Не-HTTP: после неудачного HTTP-запроса читается баннер и пишется протокол —
  `open: SSH`, `бинарный протокол`, `текст без HTTP`.
- Стек сервиса берётся не только из `cwd`: если процесс стартовал из `/`,
  каталог вытаскивается из командной строки (`php -S ... -t /srv/warehouse`) и
  из любого pid в строке `ss` (у php и node их несколько).
- `tools/check_cup.py` и `tools/cup_report.py` — прогон по репозиторию Кубка и
  сводка по нескольким сразу.
- TLS: если порт отвечает рукопожатием, живость проверяется по `https://`, а не
  по `http://` — сервисы на tls1.3 (archive, warehouse 2025) больше не выглядят
  «порт открыт, ответ не HTTP».
- Инфраструктурные правила для k3s-манифестов: `image: …:latest`,
  `privileged: true`, `hostPath`, дефолтные ключи MinIO.
- `#include` и `#define` в C/C++ больше не считаются комментарием: правило
  boost-архива срабатывает на строке include.

Чего на этих Кубках не хватило: логика без регулярки (права на объект внутри
ORM, сборка чужого объекта в ChessBase, обход проверки при малом `limit`),
бинарники без исходников, не-HTTP протоколы (qdb виден как «порт открыт»), и
`app.UseExceptionHandler`-класс ошибок. Это следующие паки, а не дыры текущих.
